# GEN2 UX 地基与偏差量化盘点

日期：2026-09-15
范围：T1–T6 当前前端与 14 个跨页面 UX 框架面
结论性质：现状审计，不代表整机验收通过，不修改产品语义

> 2026-09-15 增量：Railway 对唯一可解析的 scene/context/workflow 目的地已接入确切 `workspaceId` 进入；Arc 已覆盖节点的右键菜单已复用同一命令模型；Locator 已补入唯一 camera/safeRect 下的画外/近边 cue。Receive、重排、溢出、Collection 进入、完整 arrival 状态和 Huabu 全命令统一仍未完成。详见 `docs/handoffs/GEN2_T2_T5_Railway具体目的地进入_20260915.md`、`docs/handoffs/GEN2_T3_右键菜单与ActionArc统一_20260915.md`、`docs/handoffs/GEN2_T2_Locator_画外抵达提示_20260915.md`。

## 结论

当前不是“前端全没做”，也不是“已经可以整页交给 Chat 复刻”。按跨页面能力面统计：

- **4 个面已有可复用地基**：可以在现有宿主和接口上继续施工；
- **6 个面地基存在但 UX 明显歪或链路未闭环**：需要先纠正去向、目标身份、入口和返回，再做视觉细化；
- **4 个面关键地基仍为空**：现在只能登记接口和状态，不能把 Figma 外观画成已可用功能。

这 14 个面来自当前 UX 总图，不是 14 个新模块，也不是“14 个页面都要重写”。同一个共享宿主可能同时服务多个面。

## 一、已有可复用地基（4 个）

| UX 面 | 目前已有 | 还不能误报成完成 |
|---|---|---|
| 项目/Shell/三现场的基础宿主 | Project、Main/Context/Workflow、单一 Huabu canvas kernel、基础路由和加载失败保留来源 | 新项目空态、所有重载恢复和全部窄宽状态仍未全测 |
| Canvas 基础承载与子现场身份 | 节点 body seam、保存队列、明确 `workspaceId → canvasId`、Context/Workflow child 进入与返回来源 | 全物种编辑、旧 Huabu 命令、所有 LOD 和相机恢复仍未闭环 |
| 基础查询与同现场抵达 | Navigator 查询、跨现场等待/取消、同现场精确 focus、画外/近边 Locator cue 已有代码与定向验证 | ColorPin producer、完整 arrival 状态/焦点恢复、Railway 接收/排序/溢出仍缺 |
| Assembly/Portal/Work View 的基础消费壳 | Assembly 独立入口、Portal 局部预览、Work View、Recovery、WaitingInput body 已接 Core 事实 | Assembly 最终瀑布流视觉、真实 Reader、完整 Workflow 三动作和 Provider 链仍未完成 |

## 二、地基存在但 UX 歪或未闭环（6 个）

| UX 面 | 具体偏差 | 纠正前不应做的事 |
|---|---|---|
| 全局入口组合 | 左 Railway 需要按具体目的地弹性生长；底部才是三现场；右侧装备/沉浸入口尚未统一 | 不能再把三个固定按钮当 Railway，也不能拿 Temporal Rail 顶替右栏 |
| 对象形态与 LOD | 物种 body 和远中近表现已有局部接缝修复，但尚未逐类确认集合、Glyth、任务卡和材料的形态/图标/动作 | 不能只把所有对象涂成同一种白卡或只靠颜色区分 |
| Workflow 装备与取用 | 手牌/卡池/Workflow 现场的角色已有方向，但“用于当前会话、打开现场、续接原会话”三动作及结果反馈未完整闭环 | 不能把任务卡变成 Main 节点，也不能把 Assembly 塞进节点 Arc |
| Glyth、会话与共用 Composer | 输入框和 Work View 已存在，项目 A→B→A 草稿归属已修；Huabu thread→Core Conversation、接收者/引用/续工全链路仍需复核 | 不能再造第二聊天历史、第二套提示词输入或把事件派发当成真实副作用 |
| Temporal Rail 正常态 | 空态可诚实显示；正常 Episode 聚合、固定密度、hover 鱼眼、wheel 时间窗的生产接线未完成 | 不能把“暂无记录”当作 Rail 已完成，也不能用普通列表替代时间组织 |
| 全局焦点与临时层 | Work View 两级 Esc 已补；搜索、Arc、Atlas、手牌、Reader、窗口同时存在时的层级和焦点恢复未全测 | 不能先堆更多浮层或让画布快捷键抢走输入焦点 |

## 三、关键地基仍为空（4 个）

| UX 面 | 缺的地基 | 影响 |
|---|---|---|
| 跨区域拖放与引用矩阵 | 材料/集合/任务卡/Glyth 到 Main、Context、Workflow、Composer、Rail、窗口的 source×target 规则、失败回源、重复投放、批量部分成功尚未闭合 | 视觉上即使画出 drop 态，也无法保证对象身份和落点正确 |
| 专业窗口宿主与 Reader | 当前仍是固定单活动窗口；float/dock/split/resize/tab、阅读位置/指定 revision、摘录引用和沉浸往返缺主链 | 不能把固定右侧容器美化成“专业窗口已完成” |
| Huabu 原有命令统一 | 生产右键菜单尚未核实，多选、复制/粘贴、撤销/重做、连线、框/组等与 Arc/快捷键的同一 intent 入口未逐项对齐 | 不能为了“看起来像 LCOS”直接隐藏 Huabu 功能，也不能保留两套竞争入口 |
| 右侧装备/沉浸悬浮栏 | 用户要求已明确，但精确来源、目标绑定、safeRect 避让和与 Workflow/Reader 的边界尚未落地 | 不能把任意临时按钮当作 Figma 定稿或拿现有底部输入栏顶替 |

## 四、目前可以交给 Chat 做外观的范围

可以先做：

- 已存在的 Navigator 静息/展开/结果反馈；
- 现有 `WindowChrome`、`SurfaceFeedback`、Portal 六态；
- Assembly 条目族和 Reader 已有正文容器的排版；
- 共用 token、图标、材质、焦点轮廓、reduced-motion；
- 不改变 handler、目标身份、路由、异步结果判断的局部视觉参数。

暂时不要让 Chat 自由重画：

- 整页 Shell 和入口拓扑；
- Railway、右侧装备栏、Temporal Rail；
- 节点总物种和 LOD；
- Professional Window 的 float/dock/split；
- 右键/多选/Arc/快捷键总命令；
- 跨区域拖放和 Glyth/续工完整链路。

## 五、推荐收口顺序

```text
1. 目标身份与入口拓扑
   Railway / 三现场 / Assembly / 右栏 / 专业窗口各自归位
2. Huabu 命令与共用 Composer
   右键、Arc、快捷键、会话输入使用同一 intent
3. 跨区域投放与集合/子现场返回
   先闭 source → action → result → return
4. Professional Window / Reader / Workflow 三动作
5. Temporal Rail / Locator / ColorPin / 全局焦点组合
6. 逐区域按 Figma 做视觉细化和浏览器走查
```

## 判定

当前最准确的描述是：

> **底层宿主已经能继续施工，但 UX 总装仍处于“4 个地基可复用、6 个地基半歪、4 个地基待补”的阶段。**

因此暂不宣布 T1–T6 完整，也不允许用“Wave 全完成”替代逐条用户旅程验收。所有后续 handoff 必须引用本盘点对应条目，明确写出是修地基、纠偏、视觉细化还是仅做状态呈现。
