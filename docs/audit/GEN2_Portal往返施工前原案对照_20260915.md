## 结论先行

原案和当前施工方向只有一个可直接收敛的最小切片：先落 P01/P02 的真实 Portal 目标预览，目标必须是显式的 `canvas` 类型与可解析 `targetCanvasId`；复用 Huabu 现成的 Space Preview scene/cache/viewport 和 Preview Workspace 的幂等 `openTarget`。这一步不创建 child routing，也不把 Assembly 的 `entityRef.id` 猜成 canvas。

当前已经存在的入口是：Portal 节点双击/Enter → `openWindow('portal-preview', target, 'canvas')` → `ProfessionalWindowStage` → `PortalPreviewBody`。当前 body 只把 `target` 是否存在映射为“部分预览/目标缺失”，没有把 scene 读出来，也没有进入目标现场。

P06 “进入 Context 子画布 → 返回 Portal 来源”仍是 GAP：没有 canonical Context identity → child `targetCanvasId` 的正式映射，没有来源 camera/selection snapshot 或 settled navigation stack，也没有返回 caller。`useLcosWorksiteNav` 只能切 Main/Context/Workflow 三个固定 surface，不能冒充 child resolver。

## 原案与 Figma 约束

采用文档明确写了：Portal 复用 `SpacePreviewNode`、`useSpacePreviewScene`、`getSpacePreviewScene`、`openTarget`，只补薄身份映射；P01（Figma `5350:1332`）是 Context 门户只读预览，P02（`5350:1490`）是局部放大且 Main 不动。P03/P04/P05/P06 是后续动作边界，不能由 P01/P02 自动外推。

因此本切片的触发与副作用必须固定为：

```text
Portal 节点双击 / Enter
→ typed target { kind: 'canvas', canvasId }
→ Professional Window / Portal Preview
→ getSpacePreviewScene(canvasId)（走既有 cache）
→ SpacePreviewViewport（局部缩放，宿主 Main camera 不动）
```

“打开目标现场”“进入 Context child”“返回来源”是独立动作。它们不能由预览点击、target 字符串匹配或窗口关闭隐式完成。

## 触发、目标身份、返回规则

### P01/P02 最小切片

目标 identity 必须是带类型的解析结果，最小形态为：

```ts
{ kind: 'canvas'; canvasId: string; source?: { canvasId: string; nodeId: string } }
```

`kind:'canvas'` 只能由已有 `data.targetCanvasId` 或正式 identity→canvas resolver 产生。`item.entityRef.id`、title、surface 名、最近打开现场都不能作为替代。没有 canvasId 时只能到“目标缺失”，不能进入或构造 child。

P01 只读预览：读取目标 scene，显示加载中/旧缓存/部分预览/失败等真实状态，主现场 camera、selection、route 不变。P02 局部放大：在 Portal preview 内调整 `SpacePreviewViewport` 的局部 viewport；不调用 Huabu 主 canvas `fitView`、`switchCanvas` 或 `requestLocate`。

### 后续 P06（本轮不施工）

来源返回必须是显式 forward navigation：

```text
Portal 来源 occurrence
→ 解析 exact Context canonical ref
→ resolver 返回 child canvas target
→ child canvas settle
→ 可选 focus source occurrence
→ 成功 settle 后才记录 Portal 来源 camera/selection
→ 显式“返回 Portal 来源”
→ 恢复来源 canvas + camera + selection
```

关闭 Portal window 不等于返回；预览失败/目标缺失/导航取消不得写入 Back 栈。drop 或 locate 也不自动 push Back。camera/selection 必须按 canvas 分开保存，不能把 Atlas/Context 的镜头复制给 Main，也不能只靠 `surfaceCanvasId` 恢复 child。

## 可实施最小施工切片

1. 在 Portal preview 的边界增加 typed canvas target adapter；只接受 `targetCanvasId`，让缺失/非法 target 继续落到真实“目标缺失”。
2. 在 `PortalPreviewBody` 内复用 `useSpacePreviewScene(targetCanvasId, enabled)`，把真实 scene、loading/stale/error/retry 交给 `LcosPortalPreview`。
3. 以稳定的 Portal preview host id 复用 `SpacePreviewViewport`，传入 `scene`、当前 host canvas id 与 host id；P02 的局部 zoom/viewport 只存 preview viewport。
4. 如需“打开目标”按钮，先沿用 `openTarget` 的幂等 reveal 语义，但动作必须明确标为预览/目标 tab；不能直接导航 `/canvas/:id`，也不能在 target 未解析时 fallback 到最近 surface。
5. 为上述 adapter/body 增加真实 caller 的静态/单测后，再做浏览器证据：P01 打开、P02 放大、Main camera/selection 前后不变、目标缺失、scene stale/error retry。

## 不可猜缺项

- Context canonical identity 到 child `canvasId` 的唯一 resolver / producer；当前 `surfaceCanvasId.context` 只是顶层 Context surface，不是某个 Context child。
- child canvas 创建与持久化 owner；不能在 Portal body 内 `createCanvas`，也不能把 Portal target 当新 Project。
- 来源 occurrence 的 canonical ref、source node id、camera/selection snapshot schema，以及 settled 后回返栈 owner。
- `openTarget` 在 LCOS Professional Window 中的最终动作语义：预览 tab、进入工作现场、打开旧 Huabu route 三者必须由产品决策区分。
- Assembly `context/workflow/scene` 的正式目标 producer；在此明确前，`assemblyOpenTargetOf` 的 `entityRef.id → portal-preview target` 只能视为局部/风险路径。
- 真实 P14–P18 状态 producer（加载、旧缓存、部分、失败、缺失）与浏览器证据；组件有状态轴不等于生产链已接。

## 验收与回滚边界

本轮没有执行 lint/typecheck/unit/build 或浏览器 smoke。施工后最低验收是：Portal canvas target 可预览；P02 局部缩放不改宿主 Main camera/selection；重复打开同 target 不创建重复 preview；缺失/错误可重试且不导航；Assembly opaque entity id 不会被当成 canvas。
