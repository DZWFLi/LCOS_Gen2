# 大框架补充核对

用户本轮明确：右侧应有悬浮栏，呼出装备与沉浸式预览。该要求纳入当前 UX 纠正；不能以 Main 临时独立手牌按钮代替完整右侧栏。

## 当前证据

- Shell 当前只挂 Main 独立 Hand 按钮及 WorkflowHandOverlay，未证明完整右侧工具栏已落地。
- Navigator 已修可输入及加载/失败状态，跨现场到达、颜色组及 Locator 的完整交互仍需核对。
- CanvasHostBoundary 复用原 Canvas 内核，chromeMode=lcos；隐藏旧控件不代表命令全部被新入口接住。
- Canvas.tsx 仍有 onContextMenu；存在事件处理不等于 LCOS 右键菜单完成，需进一步逐项核菜单内容和入口。
- 九面收口文档明确专业窗口浮动/停靠由 Shell 协商，Context child canvas 的 Temporal Rail 是局部仪器；不能把它当全局右侧装备栏。

## 必须补齐的框架核对

1. 右侧悬浮栏：装备、沉浸预览的入口、显隐、互斥和退出。
2. 全局导航：顶部搜索/颜色组、左 Railway、底部三现场和右侧工具各自职责。
3. 命令入口：空白右键、节点右键、多选、关系操作，与 Arc/快捷键共享能力。
4. 预览和窗口：就地预览、沉浸预览、专业窗口之间如何进入与返回。
5. 原 Huabu 能力迁移：逐条记录旧入口、新入口、保留命令、真实验证；不能笼统称“已规划所以已保留”。

本次只核对和归档，未因用户补充临时新增一套 UI。原卡精确来源未确认的项目标待核实，不声称历史已定。
