## 当前真正缺设计细节的部分

- 右侧悬浮栏的当前组合：用户目标已明确，旧 Figma 两类装备不能混用；应按真实对象分开承接。
- 原九面交付明确未逐项绘制的 Railway Receive/重排/溢出、窗口停靠拆组、窄宽恢复组合。先沿用动作规格，不允许施工者自行改变产品去向。
- 跨区域拖放中原卡未列明的源目标组合，需回原卡和真实能力核对；不存在 producer 的动作不能先造成功 UI。

其他大多属于已定规则未落地，不该再向用户重复索要设计。

## 本轮实际修复

1. `lcosShellStore.openWindow` 按完整 target 等值复用。无目标 Reader 请求不再误打开上一份材料。
2. `openAssembly` 复用现有随机窗口 ID 方式，两个不同目的地同毫秒打开不会撞 ID，选中／关闭各自独立。
3. `ProfessionalWindowStage` 在当前会话内 Composer 可见时让出 Esc；一次收起输入，再一次关闭窗口，草稿仍在。隐藏的其他会话 Composer 不阻止关闭当前窗口。
4. Navigator 点当前已投影结果后收起搜索；除绑定外核查当前 Huabu nodes，旧绑定不触发假定位或收起结果。
5. Atlas 切项目取消旧请求，迟到响应/错误不覆盖当前项目，卸载取消；子现场进入通过既有 Workspace/canvas 映射，不新增第二画布 runtime。

前：目标缺失 → 复用旧材料；两个目的地 ID 可能碰撞；Esc 同时关闭父窗口和输入。

后：目标缺失 → 自己的不可用 body；各目的地独立；Esc 沿当前 Composer→窗口退出。

只改变既有 UI intent 与关闭条件，不新建领域数据、导航平台或数据库。对应原案：专业窗口 `5388:27165 / 5392:6085` 的目标保留与最上层退出；Reader `5388:27411 / 5392:6127` 的目标不偷偷替换。

## 施工顺序

先修目标归属、响应串线、入口一致性；搜索/Railway 抵达与集合 child 往返已有局部真实链路；继续接工作流三个动作及窗口阅读恢复；最后做跨区域拖放与全浮层组合验收。右键和旧命令迁移按命令清单逐项接，不能一刀隐藏。

后续美化可以并行处理已确认的组件外观，但不能改变上述对象、入口、去向或把未接动作画成可用。
