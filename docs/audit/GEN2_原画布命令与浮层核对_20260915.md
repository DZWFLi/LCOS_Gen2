# GEN2 原画布命令与浮层核对

> 总装补充：需要的是逐级退出和焦点恢复的正确行为，不预设必须新增全局栈或统一平台。优先复用既有hook/事件协调。旧全局NodeToolbar隐藏与每种节点的NodeFloatingToolbar退役是不同范围，不能由前者推断所有未覆盖节点的原按钮均消失；逐类型入口仍需核验。

## 结论先说

Huabu 的选择、拖动、缩放、键盘命令、剪贴板、历史、连线和部分框操作仍由唯一 Canvas kernel 持有，机械没有被删掉。Gen2 已接通的产品入口是：单节点 `LcosActionArc`、单边 `LcosEdgeArc`、Huabu 原生键盘监听，以及 Canvas 内的 Core-first connect seam。

当前真实缺口有四个：

1. Canvas 的 `onContextMenu` 只 `preventDefault()`，没有右键菜单，也没有把右键动作接到 Arc/键盘共用命令。
2. Arc 只对六类节点出现（`note/image/video/audio/canvasRef/nodeRef`），多选没有 Arc；`text/frame/sketch/question/pdf/office/web` 继续依赖旧壳或键盘。`chromeMode="lcos"` 隐藏旧 NodeToolbar/EdgeStyleToolbar，因此框/组等旧可见入口没有对应的 LCOS 新入口。
3. 复制粘贴、撤销重做、删除、编框主要是“继承 Huabu 全局监听”的能力，不是 Gen2 命令面统一接入。尤其 Core 绑定节点：Arc 的 `delete` 明确禁用并提示去 Core 删除，但 `Delete/Backspace` 仍会调用 Huabu `deleteNodes`，投影随后可能重新出现，语义不一致。
4. Esc 是多个局部 listener 各自关闭（搜索、在哪、Composer、待放置节点等），没有统一的 overlay/focus 栈。Arc 没有自己的 Esc handler；更多面板、选择、窗口前置和关闭后的焦点恢复未形成一条可验证的逐级链。

## 右键、Arc、快捷键与 Esc

### 右键

`Canvas.tsx` 根节点的 `onContextMenu` 会在非 input/textarea/select/contenteditable/link 目标上调用 `event.preventDefault()`。这只阻止浏览器原生菜单，源码没有 context menu state、菜单组件、命令 dispatch 或选中对象/空白区分。因此结论是 **GAP：右键入口不存在**，不能按 `preventDefault` 认定右键菜单已接通。

### Arc

`LcosActionArc` 只在“恰好一个节点被选中且类型属于 `LCOS_STANDDOWN_TOOLBAR_TYPES`”时挂载；打开专业窗口或 Composer 时隐藏。命令模型真实覆盖六类节点的进入、引用、转换、尺寸、强调色、适合画面、移动现场和删除等有限动作。表外类型返回空数组，并继续保留旧可见壳的意图；但 `chromeMode="lcos"` 已统一隐藏 `NodeToolbar`/`EdgeStyleToolbar`，所以框/组、文本等未被 Arc 覆盖的可见命令需要单独处理，不能写成“Arc 已覆盖全部编辑”。

`LcosEdgeArc` 仅在恰好一条边被选中且能读到 SVG 中点时出现。它覆盖线型、线样式、方向、宽度、颜色和断开；这是边局部入口，不是全局右键菜单。

### 快捷键

Huabu `useCanvasShortcuts` 注册 capture-phase keydown/paste：Delete/Backspace 删除、Cmd/Ctrl+Z 撤销、Cmd/Ctrl+Shift+Z 重做、Cmd/Ctrl+C/V 剪贴板、Cmd/Ctrl+G 编框、Cmd/Ctrl+± 缩放、Space 临时平移、Enter 编辑唯一选中边标签。它仍挂在 Canvas 上，属于内核能力复用；本轮没有发现 Gen2 把这些动作重新集中到 `LcosNodeCommandId` 或一个统一 action dispatcher。

### Esc 与浮层焦点

- 待放置节点：`Canvas.tsx` listener 调 `exitPendingNodeType()`。
- 搜索岛：`LcosNavigatorIsland` 的 Esc 清空搜索并回静息；输入框打开时显式 focus，定位后 blur。
- 在哪浮层：`LcosFocusWhere` 的 Esc 直接 `setOpen(false)`。
- Composer：`LcosComposerHost` 使用 `useCloseOnEscape`。
- Arc：没有自己的 Esc handler；选择变化 effect 只收起“更多”，不负责恢复焦点。
- 专业窗口/Atlas/手牌等由各自 surface/store 处理，当前未证明“窗口前置 → Arc 让位 → Esc 返回上一层 → 焦点回到触发控件”的统一栈。

因此当前证据支持“多个局部浮层能被 Esc 关闭”，不支持“全局 Esc 逐级退出与焦点恢复已完成”。

## 最小后续核验清单

1. 在 Main 中分别点空白、单节点、多选节点、边，实测右键是否有菜单；目前按源码应为 GAP。
2. 实测 Cmd/Ctrl+C/V、Z、Shift+Z、G、Delete 与 Arc 的同一动作是否落同一 owner、同一 undo step；重点确认 Core bound 删除不会出现“键盘删掉后立即重新投影”的误导。
3. 实测 frame/组/解组/布局在 `chromeMode="lcos"` 下仍有用户可见入口；目前只确认快捷键和底层 command，未确认新 UI caller。
4. 组合搜索、在哪、Arc 更多、Composer、专业窗口、Atlas、手牌，逐次按 Esc 并检查 activeElement、窗口前置和返回选择；现有 listener 不能替代这条证据。
