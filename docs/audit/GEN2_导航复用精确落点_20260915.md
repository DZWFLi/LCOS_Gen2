## 结论

可直接复用的导航基础已经有四层：

1. **canonical target 纯函数**：`resolveCanonicalConversationTargetV1`、`resolveCanonicalWorkViewTargetV1`、`resolveCanonicalViewTargetV1`，以及收件回执的 `targetFromCaptureReceiptV1`。
2. **occurrence / focus 纯函数**：`focusOccurrenceV1`，失败时返回 `not_projected` / `partial`，不猜 `(0,0)`，不写 camera/selection。
3. **camera/arrival 状态机**：`reduceLocatorState` 与 `reduceArrivalState` 已定义 `travelling → camera-settled → arriving`，并支持取消。
4. **Huabu 真实 caller**：`useLcosWorksiteNav` 负责 Main/Context/Workflow 顶层切换；`LcosCanvasCommands` 是唯一 shell camera/locate 请求消费者；Huabu `Canvas.tsx` 的 `onMoveEnd` 将 settled viewport 写回每 canvas 的持久镜像。

但是，**P06 所需的“Context canonical identity → child canvasId → 进入 settled → 返回来源”目前没有可复用的完整链**。现有 resolver 不含 `canvas` target，`useLcosWorksiteNav` 只处理三个固定 surface，`ContextAtlasStage`/`ContextWorksite` 只做当前 Context 投影定位，未保存来源 camera/selection，也无 back/return caller。

## 真实 caller 与当前行为

### 顶层 worksite 切换

`LcosFocusWhere` 通过 `useLcosWorksiteNav` 将跨现场 row 的 `main/context/workflow` 传入 `switchWorksite`。它依据 `surfaceByWorkspace` 把 Core search 的 workspace location 映射为三种 surface；映射失败显示 unknown，不假定位。`switchWorksite` 取得现有 canvas 或调用 `ensureCanvas`，然后真实调用 Huabu `switchCanvas`，最后 replace `/projects/:projectId/:surface`。该链没有 child canvas、来源快照或返回栈。

### Context Atlas / Context Worksite

`ContextAtlasStage` 的 `focusOnCanvas` 只是调用 `onEnterSurface(item)`。`ContextWorksite.enterItem` 反查 `useLcosReferenceStore.nodeEntityRefs`，只有当前 Context 已有投影时才 `requestLocate({surface:'context', canvasId?, nodeId, status:'projected'})` 并关闭 Atlas；没有投影返回 false，Atlas 保持打开。这里的 `item.entityRef.id` 只用于找当前节点，未生产 child `canvasId`。

### Camera 与 settled

`LcosCameraControls` 只发 `requestCamera('zoom-in'|'zoom-out'|'fit')`。`LcosCanvasCommands` 消费这些请求并调用 RF。Locate 请求只在 `locateRequest.surface === activeSurface` 且有 `nodeId` 时调用 `focusNodesOnCanvas`，随后立刻 `consumeLocate()`；这里没有 `onMoveEnd`/settled 通知给 LCOS arrival reducer。Huabu `Canvas.tsx:1581` 的 `onMoveEnd` 负责 `resumeHeightCommits('viewport')` 和 `setViewport(viewport)`，这是 viewport persistence 的真实 settled caller，但当前未与 `reduceArrivalState` 或导航历史连接。

### Portal

`PortalNodeBody` 从 `data.targetCanvasId ?? data.canvasRef` 读取字符串，并以 `targetKind:'canvas'` 调 `openWindow('portal-preview', ...)`。`PortalPreviewBody` 只在 `targetKind === 'canvas'` 时调用 `useSpacePreviewScene(canvasId)`，复用 `SpacePreviewViewport`；未显式 typed canvas target 则显示“目标缺失”。当前已有 P01/P02 预览链，但没有“打开 child 工作现场”或“返回 Portal 来源”动作。

## 对施工卡 / Figma 的对齐判定

T2/Figma 对 Context 的要求是“集合进入 → 加载 → 真实节点操作 → 返回并恢复 camera/selection”；Atlas 是当前 Context 的集合选择层，child canvas 是真实自由操作空间。Figma 采用清单同时明确“三个 Worksite 各自保留 camera/selection/layout/history”，并把 Portal 六态与“预览/打开现场/续接原会话”分开。

当前代码已对齐的部分：

- 顶层三现场用真实 `canvasId` 切换，失败不冒充成功。
- locate/focus 对 projection failure、live node 缺失、取消有明确结果，不落 `(0,0)`。
- Portal 预览 typed gate、scene cache、局部 zoom 与宿主 Main camera 隔离已经接通，且有 `PortalPreviewBody.test.tsx` 的局部 zoom / missing / stale / retry 证据。
- Preview Workspace 的 semantic identity / reveal / transient 机制可借鉴幂等打开语义。

尚未对齐的关键部分：

- 没有 `CanonicalNavigationTargetV1` 的 `canvas` 分支，也没有 exact Context identity → child `canvasId` producer/resolver。
- 没有 child enter 的真实 caller；`useLcosWorksiteNav` 不能把 Context surface 当 child。
- 没有以 canvas 为 key 的 camera、selection snapshot schema，亦没有 settled-only push/back owner。
- `LcosCanvasCommands` 消费 locate 后即清 request；没有把“RF move end settled”与 `reduceArrivalState`/return stack 串起来。
- 没有显式返回 UI / caller；关闭 Portal Window 只是 window topology 操作，不等于返回来源现场。

## 建议的最小复用施工落点（仅审计建议）

1. 先在 `apps/web-gen2/src/navigation/canonicalTargetResolver.ts` 增加**显式 typed canvas target adapter 的契约位置**，输入只能来自 Core producer 的 `canvasId`；禁止从 `entityRef.id`、title、surface 名推导。已有 `resolveCanonical*` 的 fail-close status 可以直接复用。
2. child navigation 的机械层复用 `useLcosWorksiteNav` 的“switchCanvas → active state → route/结果”顺序，但需另有 child resolver/owner；不要扩展 `LcosSurfaceKey` 来伪装 child。
3. camera/selection snapshot 应以 `canvasId` 为 key，在 child 成功 settled 后才允许入 return stack；可复用 `reduceArrivalState` 与 `focusOccurrenceV1`，但不要把 reducer 当持久化历史。
4. 把 Huabu `Canvas.tsx:onMoveEnd` 作为 settled 事件接缝候选，经 `LcosCanvasCommands` 或既有 seam 透传给 navigation controller；不得在 shell store 复制 RF viewport truth。
5. P01/P02 继续复用 `PortalPreviewBody` / `SpacePreviewViewport`；“预览”与“打开现场”按钮必须分别接到 preview 和 child navigation，不能由窗口关闭隐式返回。

## 最终审计判定

**已有 canonical child 目标映射：没有。** 当前最接近的是 Portal `targetKind:'canvas'` + `PortalPreviewBody` 的 typed gate，以及 Huabu Preview Workspace 的 semantic target 幂等模型；它们足以支撑 P01/P02，但不足以支撑 P06 往返。

**最值得直接复用的 caller：** `useLcosWorksiteNav.switchWorksite` 的真实 canvas 切换顺序、`LcosCanvasCommands` 的唯一 RF camera/locate 消费面、`Canvas.tsx:onMoveEnd` 的 viewport settled 写入点。

**最明确的缺口：** child identity producer/resolver、按 canvas 分离的来源 camera/selection snapshot、settled-only return stack、显式 return caller，以及把 Huabu move-end 事件接到 arrival/navigation 状态的薄 seam。
