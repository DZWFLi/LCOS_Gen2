# GEN2 UX 纠正与后续视觉交接

本轮由三个 Luna 子代理分别处理 Assembly、Arc/Composer、Context/Workflow，由总装复核源码及浏览器组合表现。当前是第一批纠正，不能写成全产品 UX 已完成。未提交、未推送。

## 已纠正

- Assembly 保持独立入口，改为可滚动瀑布流；无真实预览时紧凑降级。材料进入 Reader，会话进入 Work View，其他对象不冒充可阅读文件。键盘和触控都有取用入口。
- Action Arc 移除 Assembly；专业窗口打开时不继续展示节点 Arc。
- Work View 复用 Composer，真实 receiver 身份确认后发送；Canvas 与 Work View 共用提示词、引用草稿和 Run 提交映射。
- Navigator 展开后立即可输入；加载、空结果、失败都不移除输入框；关闭后忽略迟到的搜索结果。
- Main 复用 Workflow 的手牌面板，可呼出和 Esc 关闭。卡池只显示真实 workflow，不把普通材料冒充任务卡。
- Atlas 不把会话、工作流全部画成上下文集合，不以更新时间冒充时间组织。缺少组织字段时使用中性形态、禁用组织切换；定位不叫进入子现场。
- 专业窗口按 Reader/Assembly/普通内容分别限制宽度，保留视口宽度约束。

## 仍不能交给美化掩盖的缺口

1. Railway 的真实 drop、排序和子现场到达链路尚未在本轮完整验证；只有目的地读投影不能算完成弹性 Railway。
2. Context 子现场真实进入、事情/时间组织 producer、Atlas approach/restore 尚缺。
3. 当前开发数据的 Context 画布出现“Space 不存在”。导航竞态和真实绑定缺失必须分开处理；没有擅自重建用户画布。
4. Professional Window 的完整拖拽、停靠、返回栈和 Reader 内容深化未在本轮完成。
5. 共用 Composer 已有真实提交映射测试，但没有在本轮触发真实 provider Run。不能称整机执行验收完成。

## 验证

- 组合定向测试：6 文件、16 测试通过（Navigator、Assembly、Atlas、Workflow、Composer 映射、Shell store）。
- 已检查的 8 个修改文件 ESLint 通过。
- 浏览器实测：搜索保留输入并返回真实结果；Assembly 加载 12 项并可滚动；Main 手牌呼出及 Esc 关闭。
- 三视图 Stage 增补实际渲染的 effect 测试，覆盖 A→B→外部 C 不反切；子代理回传 4/4 通过及 Huabu typecheck 通过，总装追加独立复跑。
- 总装浏览器确实可访问 5273，Context 显示“Space 不存在”；未确认具体绑定请求的 HTTP 状态。子代理关于本机没有运行实例的描述与总装实测不符，不采纳其环境结论。
- 没有运行全仓发布验收，现有工作区还包含前序后端与前端改动，不能把整个 diff 都归入本次。

## 给网页 Chat 的后续工作顺序

UX 缺口解决并审查后，再把相应提交提供到 GitHub。Chat 必须先确认实际分支和 commit，读取本文件、全前端 UX 对照表和目标组件，再按指定 Figma 节点逐个美化。仓库当前本地未推送内容不能声称已供 Chat 读取。

顺序：Shell/Navigator/Railway/Dock → Main 节点与 Arc/Composer → Assembly/Professional Window/Reader → Context/Atlas/Temporal Rail → Workflow 手牌。

每次只处理一个已经明确交互的区域：复用当前组件，调整视觉参数、内容密度、状态与动效；实际页面与对应 Figma 画面一起复核。遇到缺少真实交互，记录并回传，不自行新增页面、输入器或替代流程。

依据：`GEN2_全前端UX_Figma总表对照_20260914.md`；Figma 全设计包的完整采用清单、九面视觉统一收口交付及 adoption 文档。用户最新裁决优先于旧原型。
