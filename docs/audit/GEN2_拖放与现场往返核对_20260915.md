## 结论先行

本轮只对已读到的几条链下结论，不能把 Semantic Drop 的局部边界外推成 Canvas 全部拖放能力。当前能证实的是：

1. 通用 Semantic Drop 能识别 payload、边缘停留和预览，但这条 preview store 的目标固定为左侧/底部 Dock，实际 surface commit 仍标为 Phase C。
2. Huabu Canvas 另有独立原生 `onDrop`：内部 Huabu payload 可新增/移动节点，桌面文件走上传后新增节点，URL/纯文本分别新增 Web/Note；这条链不能与 Semantic Drop preview 混写，当前只静态核到 caller，未做浏览器实测。
3. Assembly 的“投放”走真实 `CoreAssemblyClient.apply`，有逐项 receipt；这是按钮调用，不是原生拖放。Workflow 卡能加入 Composer 草稿；Atlas 能对已有投影发定位；Portal 能打开 Professional Window 并展示“部分预览/目标缺失”。

集合进入真实 child、Portal → child → 来源返回、Workflow 卡的打开/续接、相机/选择恢复均没有在本次已核到的 LCOS 专项 caller 中形成完整可验证链。Canvas 原生文件/URL/文本导入的存在，不代表这些现场往返链已接。更新时间字段只用于显示，不能当作时间组织轴；Atlas 当前“定位”也不能当作“进入”。

状态词：**已接**=代码有真实 caller 与动作；**局部**=只覆盖链路的一段；**缺失**=当前 caller 明确没有该动作；**未验证**=源码可见但没有浏览器/运行证据。

## 集合 / Portal / Workflow region child 往返链

### 集合 → Context child → 来源

原案是 Atlas/Collection 进入 Context 子画布，保留对象身份、进入后可编辑，返回恢复来源 camera/selection（Figma P06、A09；九面收口 Context 操作去向）。

当前实际链：`ContextWorksite` 打开 `ContextAtlasStage` → Atlas 读取 warehouse → 对已有 node ref 调 `requestLocate({surface:'context', nodeId})` → 关闭 Atlas。`useLcosWorksiteNav` 只负责三个固定 surface 的 canvas 切换（`useLcosWorksiteNav.ts:36-52`），没有 collection/child canvas 映射。

结论：**局部**。这里是“定位已有投影 + 关掉 Atlas”，不是“进入 child”。`scene` 卡直接写“进入子现场不可用”；事情/时间两个组织按钮也因没有真实字段而 disabled（`ContextAtlasStage.tsx:65-84`）。更新时间只作为卡面 `updatedAt` 文案（`ContextAtlasStage.tsx:112-115`），不构成时间组织。

### Portal → 目标现场 / child → Portal 来源

原案要求 Portal 预览、提升到装配/工作台、进入 Context child，再回 Portal 来源，且来源 camera/selection 可恢复（P01–P06、P14–P18）。

当前实际链：Portal 节点双击或 Enter → `openWindow('portal-preview', target)` → Professional Stage 挂 `PortalPreviewBody`。`PortalPreviewBody` 只根据 target 是否存在输出 `部分预览` 或 `目标缺失`，并把 target 与已知三 surface 的 canvasId 做字符串匹配；没有 `openTarget`、child canvas、来源栈或恢复动作。

结论：**局部**。Portal 窗口入口已接，目标现场渲染与返回链**缺失**；P14–P18 的加载/旧缓存/失败/缺失等完整状态也没有生产数据源，当前仅有组件轴和两个真实可达状态。未做浏览器点击/重载验证。

### Workflow 手牌 / region → 当前会话 / Workflow 现场 → 续接返回

原案要求三动作分开：用于当前会话、打开 Workflow 现场、续接原会话；卡片不先造 Main 节点（B03–B17）。

当前实际链：Workflow 现场按钮打开 `WorkflowHandOverlay` → `WorkflowCardPool` 读取 warehouse 中 `workflow` → “取用”调用 `addEntityToDraft`。同卡 footer 的“打开”是静态 `打开（尚未接入）`；未见 region child、Run/原会话 identity、续接或返回来源 caller。

结论：**局部**。取用进草稿已接，打开/续接/返回**缺失**；“workflow 真实现场”仅由固定 surface 的 `LcosWorksiteStage` 提供，不能当作从某张卡进入对应 region child。未验证草稿跨 reload 或返回焦点。

## 现场导航与时间语义核对

- `useLcosWorksiteNav` 的 `switchWorksite` 只接受 `main | context | workflow`，找到或创建对应 canvas 后调用 Huabu `switchCanvas` 并改 route；这是 surface 级导航，**不是**集合/Portal child 进入。
- `LcosWorksiteStage` 对固定 `canvasId` 做 load/switch，并支持失效画布重建回写 workspace；这是现场恢复，**不是**来源返回栈。
- Atlas 当前按 `buildAtlasGroups(items)` 分组，但生产 UI 的“事情/时间”控件均 disabled，且显示 `updatedAt` 只是更新时间；审计不将其描述为时间组织已接。
- `LcosDropState` 的 `commitAt` 只把 preview 转成 confirming/committing 状态，注释明示 concrete surface write 尚属 Phase C；所以不能从状态机存在推导实际投放完成。
