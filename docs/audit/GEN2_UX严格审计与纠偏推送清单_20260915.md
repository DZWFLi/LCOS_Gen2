# GEN2 UX 严格审计与纠偏推送清单

更新：2026-09-15

## 结论

本轮确认的范围是连续 UX 纠偏链：

```text
Shell / Railway / Dock
→ Main 节点与 Action Arc / Composer
→ Assembly / Reader / Professional Window
→ Context / Atlas / Temporal Rail
→ Workflow 手牌
```

这不是把 DeepSeek 前一轮实现重新包装成完成，而是在其基础上逐项修正入口、对象身份、目标去向、返回关系和失败态。本次只准备推送 Huabu 前端的 UX 纠偏及对应证据文档；`apps/local-core`、续工服务、provider/transport 和未归属于本链的 Trae 改动不进入本提交。

## 已核实并纳入本次推送的内容

- Railway 只显示可解析的具体目的地；三根根现场入口留在 Surface Dock。
- Navigator 搜索保留真实输入，迟到结果不会覆盖当前现场；“在哪”只对真实绑定对象定位。
- Main 的 Action Arc 与右键命令共享同一命令模型；Assembly 不再伪装成 Arc 命令。
- Composer 不再作为永久底栏；Canvas 与 Work View 共用真实 receiver、草稿和提交映射，Esc 按 Composer → Window 逐级退出。
- Assembly 独立为内容优先瀑布流，取用路径按材料身份进入 Reader、Work View 或明确的 Workspace 选择。
- Reader 使用现有 Core artifact/revision/content 读取，未把占位内容伪装成正文；不支持的格式如实保留。
- Context Atlas 只接受真实 context/collection/scene 投影，不用 `kind` 或 `updatedAt` 猜“事情/时间”；缺组织字段时保持中性并禁用不可证实的筛选。
- Context/Workflow 子现场按真实 `workspaceId → canvasId` 进入，复用同一 Huabu kernel，并保留返回来源。
- Workflow 卡池只呈现真实 workflow，不把 artifact 或 conversation 卡片化；请求在项目切换/卸载时可取消，迟到响应不会串项目。
- 节点物种、绑定节点删除保护、加载失败保留来源、导航重入、窗口目标等局部纠偏已有针对性测试。

## 审计中修复的两个真实缺陷

1. Atlas 集合列表缺 React `key`，会造成列表身份不稳定和控制台警告；已按实体身份补 key。
2. Workflow 卡池请求未取消，跨项目切换时旧响应可能覆盖新项目；已加入 AbortController、active guard 和 cleanup。

## 仍然是明确 GAP 的内容

- Railway 的 Receive、排序、溢出和 ColorPin/Locator producer 尚未完成整条真实抵达链。
- Context 的事情/时间 producer、Atlas approach/restore 尚未有真实来源，不能用推测字段替代。
- Professional Window 当前仍是单活动固定浮层；dock/split/resize、窗口分组和完整返回栈未完成。
- Reader 的指定 revision、阅读位置恢复、摘录/引用和沉浸往返未完成。
- Workflow 三动作（用于当前会话、打开现场、续接原会话）尚未全部由真实 producer/caller 打通。
- 真实 provider 驱动的 Run → waiting_input → answer → artifact return → review/retry 未完成整机验收。
- 浏览器首页验收受当前开发数据缺 World canvas 阻塞；没有把缺数据重建成用户画布，也没有把脚本跑到末尾当作成功。
