# T2 搜索抵达与“在哪”异步纠偏

日期：2026-09-15。状态：局部实现并验证，T2 尚未全量收口。未提交、未 push。

## 本轮改变

- Navigator：当前现场真实节点可直接定位；跨现场结果先列出 Core 返回的位置，由用户选择，再切换现场并等到真实 binding 和 node 同时就绪，最后调用既有相机定位。没有位置不猜目的地。
- 等待超时保留结果并说明投影尚未就绪；关闭搜索、修改查询、项目切换取消等待，迟到结果不再触发定位。
- Worksite navigation：旧项目请求完成后不再改新项目的路由与 activeSurface。
- “在哪”：关闭、卸载、项目切换、新查询后旧响应失效；同现场 occurrence 只列当前画布实际存在的节点，点击精确定位并关闭面板。后续增量已为跨现场行复用 waitForProjectedEntity，切换后等待节点再定位，取消阻止迟到定位。
- Canvas command consumer：定位请求必须属于当前 canvas，且节点确实存在，才移动相机。

流程：搜索 → 选择真实位置 → 切换既有 worksite → 等待节点和身份抵达 → 既有相机定位。取消/超时不伪造抵达。

## 实测发现，不能写成完成

1. 开发库的 artifact-positioning/rules/milestone 搜索结果 locationRefs 为空。只读审计确认默认 seed 只填 focusedViewIds，没写 workspace_memberships；Artifact 的合法成员关系仍走 ArtifactView，不能混入只支持 note/scope/workspace/conversation 的 entity memberships。projection_bindings 也不能冒充 semantic membership。暂不改 seed 来制造通过。跨现场 UI 的测试通过不等于真实生产数据全链已通。
2. Main 原生 Type... 已查明为 text 漏接物种 body，并已补齐及修复零高度，详见 `GEN2_T1_Text承载节点物种接缝修复_20260915.md`。未绑定历史节点仍保留，不将本截图作为完整物种形态验收。
3. 后续已实证“在哪”用实体 ID 搜全文返回空；现已改为直接复用导出的 SqliteBindingStore.list()，按 project/entity/type/node binding 精确过滤，再用既有 canvasBySurface 映射。没有新增接口，也没有将投影当成员关系。真实浏览器选中 artifact-positioning、F 列出 Context/Workflow、点击 Context 并抵达关闭面板已通过，截图 `t2-where-real-locations.png`、`t2-where-arrived.png`。ColorPin、Locator、Railway 的全部动作仍按总表列缺口。
4. 本轮没有修改数据库、用户画布坐标，也没有宣称真实 provider 执行通过。
