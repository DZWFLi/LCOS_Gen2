# T1 / T3 / T4 项目切换与草稿归属

## 本轮范围与依据

沿用 `docs/audit/GEN2_阅读窗口与项目归属核对_20260915.md` 中明确的项目串目标问题；Figma 九面交付的窗口目标保留、Reader 不偷偷替换来源，以及用户要求“UX 正确、复用现有机制”。

本轮修改现有 Zustand shell/reference 状态和异步调用归属，不新增领域实体、数据库、跨系统协议或通用导航平台。这里解决同一次打开应用期间的项目切换；没有把内存保存当成重启恢复。

## 用户操作前后

```text
之前：A 的窗口 + 提示词 + 引用 → 切 B → 继续由全局状态提供给 B
      A 的提交迟到成功 → 清空当前提示词（可能已属于 B）

之后：A → 保存 A 的窗口/提示词/引用 → 激活 B 自己的 UI
      B → 返回 A → 恢复 A 的窗口/提示词/有序引用
      A 的提交完成 → 只清理 A 同目标、未改写的已提交提示词
      项目切换 → 旧相机/定位请求不重放；绑定缓存重新读取
```

## 风险和边界

- 缓存仅在当前浏览器应用生命周期内，重载会丢失；重启恢复仍需原卡规定的持久化接线。
- 返回后保留目标不代表目标仍合法；body 继续从 Core 读取并如实呈现失效。
- 仍不保存第二份画布位置或选择真相；一次性相机/定位请求清空而不是重新执行。
- 已开始的外部请求不被当作未发生；媒体上传若已发出，可能在原画布留下可再生呈现资产，不得把结果写到新画布。
- 回退只撤销本批文件中的新增局部差异，保留其它已授权施工；禁止整个工作树重置。
