日期：2026-09-15。当前工作区增量，未提交、未 push。属于原有“进入真实现场，失败不冒充抵达”的实现；不是新增产品流程。完整子现场进入与来源返回仍未完成。

## 原因和操作变化

原路径：GET 非 404 错误也返回 null → store 已先切 canvasId → 失败留下旧 nodes 与新身份 → switchCanvas 仍 resolve → LCOS 更新 URL 并报告切换成功。网络错误还会被误导为“画布不存在”，提供重建。

现路径：等待现有保存流程 → 读取及预热目标 → 成功后提交目标身份、节点、预览与历史 → true 才更新 LCOS URL。失败返回 false，保留来源身份、内容、镜头及冲突状态，显示真实原因。直接 URL 进入失败时显示重试；只有对应目标的 404 显示不存在与重建。

若用户在目标尚未加载时选择仍在的来源现场，旧请求失效，晚到结果不能把用户带走。不同请求的 fetch 与 warmup 都检查当前请求，避免旧响应覆盖新目标。
